# 对话授权与单执行方案核证

用于对话型 Agent 的认证、授权、业务写入及恢复方案。它是设计审查流程，不是已验证的现成确认桥实现，也不固定具体项目的端点或留存数值。

## 1. 固定产品边界与来源版本

1. 读取用户已确定的交互原则及当前项目约定，区分调查、制定方案、实现、部署的授权范围。
2. 记录源码版本与相关未提交变更；核对并行任务的真实交付，不把别人计划处理的测试当成已修复。
3. 写一份唯一可执行合同，事实、拟新增接口、未验证点分别标记；短附录若优先替换正文，列出精确替换范围并消除冲突，不让实施者在多份方案中自行选规则。
4. 将正常读取、单条写、批量写、删除、撤权分别纳入确认矩阵；关闭与删除等不同动作不能静默互换。

## 2. 从真实入口追踪三条链

分别追踪人消息入口、Agent 工具调用、服务端执行：

- 对每个主体标明身份域：平台人用户、DE/设备、职责/profile、外部业务账号。用平台权威接口验证人对目标 DE 的当前访问归属；外部账号及其 generation 只证明执行身份，不得互比两个域的 ID。
- 区分宿主 cookie、机器 Bearer 与人用户确认；机器 write scope 不构成人用户授权，本地会话有效也不证明平台归属尚未撤销。
- 追到真实运行时注入点、MCP/适配器透传及 handler 消费点；仅发现接收字段不能证明上游生产该字段。缺失的符号或作用域机制列为有界技术验证，不以“宿主会注入”代替设计。
- 为消息上下文选择宿主管理的关联方式；不让模型自报用户、会话或权限，不用共享全局变量承载并发 turn 的身份。后台任务无当前人消息上下文时，不得借历史聊天提议或批准新写操作。

## 3. 先验证正常对话，再验证隔离

先写完整正例：用户第 N 轮提出操作 → Agent 准备精确载荷 → 宿主展示摘要 → 同一用户第 N+1 轮确认 → 单次执行 → 回执 → 原任务续接。

- 将提议来源 turn/message 留作不可篡改追溯，不把它当确认轮匹配条件；确认使用后续人消息自身的可信上下文。
- 分开调用上下文 token 的生命周期与 pending 的有效期；提议轮结束不应使未过期提议无法确认。
- 按用户、真实会话、通道、目标 DE、职责/profile 校验确认来源；不同会话不得互相覆盖或批准。需支持跨通道时另定义身份关联协议，不靠相同显示名称放行。
- 对裸“确认/取消”仅在当前作用域唯一待确认时解析；多个候选要求明确标识。
- 权威摘要须由确定性宿主通道按实际执行载荷生成和发送；模型转述不是载荷一致性证据。区分发送回执、用户已读与用户同意，三者不能互相替代。

随后添加负例：跨用户/会话/目标、并发上下文串用、改口、取消、过期、换账号、权限吊销、摘要发送失败、模型输出伪造确认。安全负例不得把正常次轮确认误写成非法路径。

## 4. 逐动作核对实际能力与强制闸

建立“任务入口 → 实际暴露工具与操作 → service handler → 上游能力 → 权限和结果语义”矩阵。

- 实跑适配器加载逻辑并核对工具集合与操作枚举；service enabled、llm_expose、MCP 白名单与 handler 可执行是不同层，不能凭配置出现工具名就断言可调用。
- 隐藏 MCP 写操作不是 ACL。测试机器身份直接请求与人 cookie 直接请求，均不能绕过本方案的确认强制点。
- 若采用宿主执行 claim，明确其唯一可信铸造点、不可由 HTTP 请求体伪造的上下文、精确服务/动作/载荷/主体/目标绑定及每个写入口的验证点。
- 为只读、创建、流转、字段更新、删除分别定义 schema 和权限映射；未知字段 ID 拒绝，不以任意 extra 字段透传绕过白名单。

## 5. 分开执行领取、副作用与结果证明

1. 定义持久化状态及唯一可执行来源，先落非 pending 执行状态再调用上游；任一必需落盘失败都不发起副作用。
2. 区分宿主领取与 service 的防重消费，明确首次合法 dispatch 必须通过、重复 dispatch 必须拒绝；批量一次服务调用的 claim 不在内部逐项重复消费。
3. 用崩溃注入覆盖领取前、领取后调用前、上游完成但回执丢失、终态落盘失败。无终态的执行残留按 unknown 处理，不能因 claim 未消费或日志到期而自动重发。
4. 分开可关联执行回执与事后当前状态。标题/时间唯一候选不证明本次创建，404 不证明本次删除；证据不足时保留未知及人工核对路径。
5. 定义最小权限、具体留存期限、正文脱敏与清理规则；清理载荷不得同时丢失未决操作的防重凭据。数值按项目批准，不把某方案的期限升级为所有项目固定规则。

## 6. 收敛与交付

- 限定本机产物检查的证据范围，不能推出远端“从未部署”；静态串行和额外请求仅是潜在成本，未采样不能称为用户等待的已证根因。
- 审查要求精确位置、触发序列、影响及最小替换；将正常时序问题、强制闸缺口和未验证技术入口一次性列齐，避免每轮追加新概念。
- 剩余精确文档替换由 Leader 无并发写入时直接修改；对正常次轮、旧错误规则移除、claim 粒度和未知边界做程序化断言，并在原审查卡记录差异。
- 文本断言只证明合同文字更正，不证明运行时安全。分别交付待批准的体验取舍、实施前技术验证门、实现测试与真实环境验收项；不要用执行者自审或报告版本数冒充独立批准与功能完成。
