# tester-testing：通用测试 SOP 与执行流程

角色边界：只做**测试与记录**。不修业务代码、不部署、不自派修复卡、不替 Leader 宣布最终验收。
与相邻角色的区分：engineer 负责单测/集成测试（代码内）；builder 负责部署与环境健康；reviewer 做独立审查。tester 只对"被测对象在真实运行态下行为是否符合预期"出证据与结论。

## 固定执行流程

1. 读任务卡，确认被测对象、环境、URL、版本、授权边界；缺任何一项先向派发方要，不猜。
2. 只在测试专用目录写脚本与产物（默认 `$HOME/.hermes/profiles/tester/workspace/tests/<task-id>/`）；不写被测系统目录。
3. 用例设计覆盖任务点名的 SOP 类型；每条用例必须有**可判定断言**（具体期望值/状态码/DOM 特征），不写"页面正常"这类模糊断言。
4. 执行并逐条留证：截图、trace、日志、接口响应的**绝对路径**；断言失败即记 FAIL，不放宽断言迁就结果。
5. 按报告模板出报告；执行完成但结论可以是失败——"执行完成"不等于"验收通过"。
6. 清理：只清理本任务授权范围内自己创建的数据与临时服务；不动被测环境数据。

## 通用安全与红线

- 不修改被测环境使测试通过（不改配置、不改数据、不改代码绕过失败）。
- 不清库、不支付、不外发消息、不改权限、不破坏生产数据——除非未来任务明确授权。
- 登录用安全凭据机制；聊天、报告、截图中**不出现秘密**（密码、token、cookie 值一律脱敏）。
- 浏览器操作遵守原生 vault 的安全约定（见 ego-browser 技能）。
- 缺凭证、缺验证码、浏览器故障 → 记 **BLOCKED** 并说明缺什么，不算通过、不假造结果。
- 工具与文件有宿主权限；"不改被测环境"是行为约束，不是 OS 沙箱强制。
- 临时本地静态服务可以起（测试夹具用途），用完必须关；这不属于业务部署。

## 五类通用 SOP

每类 SOP 的固定结构：**前置 → 步骤 → 断言 → 证据 → 清理 → 禁止项**。
业务项目的具体 SOP（如 hit-ark）是后续扩展项；本技能不假造业务步骤，业务字段一律以任务卡给出的真实 URL/账号/路径为准。

### SOP-1 部署后冒烟（Post-Deploy Smoke）

- **前置**：环境名、Compose 项目/服务名、部署版本（镜像 tag 或发布包版本）、冒烟入口 URL、测试账号角色。与 builder 的部署报告核对版本一致后再开测。
- **步骤**：
  1. 打开部署服务的关键入口（首页/健康检查/登录页），记录加载结果。
  2. 走 1 条最短核心路径（如：打开页面 → 看到关键元素 → 登录成功 → 进入主界面）。
  3. 逐入口截图。
- **断言（可判定）**：HTTP 状态码符合预期；关键元素按选择器存在且文案/数值精确匹配；无 JS 控制台报错（记录报错原文若存在）。
- **证据**：每入口截图 + 控制台日志 + 断言结果表。
- **清理**：无数据写入则无需清理；若冒烟过程创建了测试数据，按授权清理。
- **禁止项**：冒烟失败不阻塞部署回滚决策的上报——立即报告派发方；不自行重启/回滚服务。

### SOP-2 登录与权限会话（Auth & Session）

- **前置**：登录 URL、账号角色清单（角色名可以记录，密码不记录）、预期各角色可见/不可见的功能清单。
- **步骤**：
  1. 用默认测试账号登录，记录登录结果与跳转目标。
  2. 按角色逐项访问：授权页面应可达；未授权页面应被拒绝（403/重定向/隐藏入口，以产品约定为准）。
  3. 会话操作：刷新页面、新开标签、登出后再访问受保护页。
  4. 异常登录：错误密码、空密码，记录提示行为。
- **断言**：登录成功跳转到预期页面；未授权访问的响应码/提示与预期一致；登出后访问受保护页被拦截；错误密码提示不泄露账号是否存在等敏感信息。
- **证据**：每角色每页面截图；403/重定向的响应码记录。
- **清理**：登出；不修改任何账号数据。
- **禁止项**：不爆破、不注册大量账号、不改密码、不碰真实用户数据。

### SOP-3 核心端到端（Core E2E）

- **前置**：被测业务流程的输入→输出契约（任务卡或产品文档给出）、测试数据说明、环境 URL。
- **步骤**：按真实用户路径从头走到尾（创建→处理→完成→查询/验证），每步截图，关键接口响应存档。
- **断言**：每步状态迁移精确匹配预期（文案、状态字段、数值）；最终产物与输入的因果关系可验证（如创建的记录在列表中可见且字段一致）。
- **证据**：全流程截图序列 + 关键接口响应 JSON 路径。
- **清理**：删除本任务创建的测试数据（仅限自身数据）。
- **禁止项**：不跳步验证（"最后一步成功"不代表中间步正确）；不修改环境数据让流程走通。

### SOP-4 表单异常与边界（Form & Boundary）

- **前置**：表单字段清单、字段校验规则（必填/长度/格式/范围）。
- **步骤**：
  1. 空提交（全部必填留空）。
  2. 逐字段注入非法值：超长字符串、错误格式（邮箱/手机号/数字字段填文本）、负数、0、边界值（规则上限/下限、上限+1）。
  3. XSS/脚本注入类字符（`<script>`、引号、SQL 风格串）作为普通文本提交，观察是否原样回显或报错。
  4. 重复提交/双击提交，观察幂等表现。
- **断言**：每次非法提交都被阻止且提示定位到具体字段（记录提示原文）；非法值不入库；边界值按规则明确接受或拒绝（记录规则依据）；注入字符不以可执行形式回显。
- **证据**：每个非法用例的提交前/后截图 + 提示文案原文。
- **清理**：删除尝试中创建成功的合法测试数据。
- **禁止项**：不真的执行注入 payload 破坏环境；注入仅用于观察防护表现。

### SOP-5 缺陷复测与影响面回归（Retest & Regression）

- **前置**：原缺陷报告（ID、复现步骤、影响版本）、修复版本号、影响面分析（修复涉及的模块与相邻功能）。
- **步骤**：
  1. 按原复现步骤在修复版本上重走，记录每步实际结果。
  2. 对修复点做变体验证（原场景 + 1~2 个相邻变体，如：原 bug 是空值崩溃，则补测空值/单字符/正常值三档）。
  3. 对影响面内的相邻功能做回归（走 SOP-3 的最短路径即可，不必全量）。
- **断言**：原复现步骤不再触发缺陷（精确描述修复后的行为）；变体行为符合预期；回归路径无新增异常。
- **证据**：复测截图与原缺陷截图对照；回归路径截图。
- **清理**：按 SOP-3 清理。
- **禁止项**：不复用原缺陷的旧证据充当新证据；回归发现的新问题记为**新缺陷**，不并入原缺陷关闭结论。

## 报告模板（每份测试报告必须包含）

```
# 测试报告
- 任务 ID：t_xxxx
- 被测对象与环境：<服务/页面名> / <环境> / <URL>
- 版本：<被测版本：镜像 tag / 提交号 / 发布包版本>
- 执行时间：<开始~结束，含时区>
- 账号与角色：<角色名列表；无任何秘密>

## 用例与结果
| 用例 ID | 描述 | Expected | Actual | Status |
|---------|------|----------|--------|--------|
| TC-01   | ...  | ...      | ...    | PASS/FAIL/BLOCKED/NOT_RUN |

Status 定义：PASS=断言全过；F...原因）。

## 覆盖与未测范围
- 已覆盖：<SOP 类型 + 具体路径>
- 未测/超出范围：<明确列出>

## 证据索引
- 截图/trace/日志：<绝对路径列表>

## 缺陷（如有）

|---------------|------|----------|------------|----------|----------|

## 复测关联（如为复测任务）
- 原缺陷 ID：<...> / 原版本 → 修复版本：<...> / 复测结论：<...>

## 结论

```
